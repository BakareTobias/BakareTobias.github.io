Sign Language Interface

A real-time hand-tracking and gesture-recognition system that translates alphabet-level American Sign Language (ASL) gestures and enables touchless computer navigation through webcam input.

The problem

Hand gestures provide a natural way to communicate and interact with digital systems, but interpreting them reliably from a webcam feed is challenging. Hand position, orientation and proportions vary between users, while visually similar poses can be difficult to distinguish.

This project addresses those challenges with a modular computer-vision pipeline. It supports an alphabet-level ASL interface and a separate set of touchless computer-navigation controls.

How it works

The system uses webcam frames to detect hand landmarks, normalize their coordinates and pass the resulting features to gesture-recognition logic.

  1. Hand detection: MediaPipe identifies hand landmarks in each webcam frame, supporting real-time, multi-hand tracking.
  2. Landmark preprocessing: Coordinates are translated relative to landmark 0 and scaled using palm width and palm height to reduce sensitivity to hand size and position.
  3. Gesture classification: A Random Forest classifier recognizes static ASL letters. An LSTM model handles the dynamic gestures for J and Z by using sequences of hand landmarks.
  4. Application output: The ASL interface converts recognized gestures into text. The touchless-navigation scripts map hand gestures to cursor movement, clicks, scrolling and volume control.

Key decisions

Landmark-based features: Rather than classifying raw image pixels, the system uses hand keypoints. Coordinates are normalized relative to the wrist landmark and scaled by palm dimensions, helping the model focus on hand pose rather than absolute image position or hand size.

Different models for static and dynamic gestures: Logistic Regression and Random Forest were evaluated for static gestures. Random Forest achieved stronger precision, accuracy and F1 performance as the number of classes increased, so it was selected for static ASL letters. J and Z require motion over time, so an LSTM was used to model sequences of landmarks.

Reducing forced-choice errors: The dynamic-gesture dataset includes an “other” class containing hand movements that are neither J nor Z. This gives the model an alternative to assigning every unfamiliar motion to one of the target letters.

Results

The current system recognizes all 26 ASL alphabet letters and additional static hand gestures. It also supports dynamic recognition of J and Z using an LSTM, alongside custom space and backspace gestures for text entry.

  • 5,000+ labelled instances collected across 28 classes for the static-gesture dataset.
  • 42 features per single-hand sample, representing the x and y coordinates of 21 landmarks.
  • Support for two-hand landmark data, represented by 86 features: 84 coordinate values and two inter-hand distance features.
  • Real-time webcam inference, with testing on live camera feeds, static images and recorded videos.
  • Touchless controls for cursor movement, left click, right click, click-and-drag, scrolling and volume adjustment.
  • Unit tests written for core modules.

Testing showed that similar-looking letters can still be misclassified. This is an important limitation when interpreting predictions in real-world conditions.

What I learned

This project developed my understanding of the complete machine-learning workflow for vision-based interaction: collecting and labelling data, preprocessing landmarks, comparing classifiers, evaluating errors and integrating inference into real-time applications.

It also highlighted the distinction between static pose recognition and dynamic gesture recognition. A single frame can describe a hand configuration, but gestures such as J and Z require temporal information across multiple frames.

Further work could focus on reducing confusion between visually similar letters, expanding evaluation across different users and lighting conditions, and improving temporal recognition robustness.
